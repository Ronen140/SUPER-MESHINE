# דרישות — מערכת חשבוניות וקבלות

מסמך אפיון התחלתי. יתמלא בשיחות ההמשך עם המייסד.

## רקע — למה בונים את זה

המייסד השתמש עד היום בשלושה שירותי הפקת חשבוניות ישראליים — **Xterm**, **Morning** (חשבונית ירוקה לשעבר) ו-**Ypay** — ולא היה מרוצה מאף אחד מהם. הכאב המרכזי: **תשלום חודשי** על צורך בסיסי של העסק. המסקנה: מערכת עצמית, ללא עלות שוטפת, בשימוש העסק של המייסד לפחות כשלב ראשון.

## תשובות מהמייסד (2026-08-30)

- **קהל יעד:** המייסד + חברים. מספר עסקים נפרדים במערכת אחת. המייסד הוא **עוסק פטור**; בין החברים יש לפחות **עוסק מורשה** אחד. ⇒ המערכת היא **רב-עסקית (multi-business)** מהיום הראשון.
- **נפח:** ~2 מסמכים בחודש לעסק, משתנה. סכום ממוצע תנודתי מאוד — ₪1,000 עד ₪10,000 ויותר.
- **כאב מרכזי מהשירותים הקיימים (מעבר למחיר):** אין דרך נוחה לפרט את פירוט העבודה במסמך; ואין תמיכה בקטלוג פריטי עבודה מוגדרים מראש **שסכומם נשאר פתוח לעריכה** עד רגע הפקת המסמך.

## דרישות שנגזרות מהתשובות

- **Multi-business:** כל עסק — פרטים, סוג ישות (פטור/מורשה), מספור רציף נפרד, לקוחות נפרדים. הרשאות: כל משתמש רואה רק את העסק/ים שלו (RLS — עקבי עם עקרון ה-multi-tenancy של הבית).
- **סוגי מסמכים לפי סוג ישות:** עוסק פטור מפיק **קבלות בלבד** (ללא חשבונית מס, ללא מע"מ); עוסק מורשה מפיק חשבונית מס / חשבונית מס-קבלה / קבלה / זיכוי עם מע"מ.
- **קטלוג פריטי עבודה:** פריטים מוגדרים מראש (שם + תיאור מפורט + מחיר ברירת-מחדל *אופציונלי*), שנשלפים למסמך וסכומם פתוח לעריכה כל עוד המסמך בטיוטה.
- **מצב טיוטה:** מסמך נשאר טיוטה — הכל פתוח לעריכה — עד פעולת "הפקה" מפורשת. מרגע ההפקה: מספר רציף, נעילה מלאה, תיקון בזיכוי בלבד.
- **פירוט עבודה עשיר:** שדה תיאור מרובה-שורות לכל שורת פריט + הערות חופשיות ברמת המסמך.
- **מספר הקצאה (חשבוניות ישראל):** רלוונטי רק לעוסק המורשה, ורק לחשבוניות מס מעל סף שיורד משנה לשנה. בסכומים של ₪10k+ זה כנראה גבולי כבר ב-2026 ויידרש בוודאות בהמשך — לתכנן את ה-schema כך שאינטגרציית רשות המסים תתווסף בלי שינוי מבני, אך לא לממש ב-MVP הראשון.

## שאלות פתוחות לאפיון

1. **מיצוב ארוך-טווח:** נשאר כלי פרטי לחבורה, או גרעין למודול Billing של SUPER-MESHINE? (לא חוסם את ה-MVP.)
2. **תשלומים:** רק תיעוד תקבולים, או גם סליקה בפועל (אשראי / העברה / ביט)? (הנחת עבודה ל-MVP: תיעוד בלבד.)
3. **רב-מטבעי:** שקל בלבד או גם מט"ח? (הנחת עבודה ל-MVP: שקל בלבד.)
4. **Stack:** ברירת המחדל של הבית (TypeScript + Next.js + Postgres/Supabase) או משהו אחר?
5. **אימות מול רו"ח:** שכל עסק בחבורה מוודא מול הרו"ח שלו שמסמכים מהמערכת מתקבלים (תאימות להוראות ניהול ספרים).

## דרישות ליבה (טיוטה ראשונית)

- הפקת חשבונית מס / קבלה / חשבונית מס-קבלה / חשבונית עסקה / חשבונית זיכוי.
- מספור רציף לכל סוג מסמך; מסמך שהופק אינו נמחק ואינו נערך — תיקון בזיכוי בלבד.
- חישוב מע"מ אוטומטי לפי שיעור בתוקף בתאריך המסמך.
- ניהול לקוחות: פרטים, ח.פ/ע.מ, יתרות פתוחות.
- PDF חתום-מראה + שליחה במייל.
- ייצוא נתונים לרו"ח.
- Audit log על כל פעולה (עקבי עם עקרונות SUPER-MESHINE).
