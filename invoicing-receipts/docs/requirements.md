# דרישות — מערכת חשבוניות וקבלות

מסמך אפיון התחלתי. יתמלא בשיחות ההמשך עם המייסד.

## רקע — למה בונים את זה

המייסד השתמש עד היום בשלושה שירותי הפקת חשבוניות ישראליים — **Xterm**, **Morning** (חשבונית ירוקה לשעבר) ו-**Ypay** — ולא היה מרוצה מאף אחד מהם. הכאב המרכזי: **תשלום חודשי** על צורך בסיסי של העסק. המסקנה: מערכת עצמית, ללא עלות שוטפת, בשימוש העסק של המייסד לפחות כשלב ראשון.

## שאלות פתוחות לאפיון

1. **מיצוב:** כלי פנימי לעסק של המייסד בלבד, מוצר עצמאי לעסקים קטנים, או מודול Billing עתידי של SUPER-MESHINE ERP? (הרקע מטה מיצוב לכלי פנימי תחילה; משפיע על stack, multi-tenancy, ושיתוף קוד עם `packages/`.)
2. **קהל יעד:** נראה שהמשתמש הראשון הוא העסק של המייסד. עוסק מורשה או חברה? כמה מסמכים בחודש? (קובע אם חובת מספר הקצאה רלוונטית כבר עכשיו.)
3. **רגולציה:** תאימות להוראות ניהול ספרים; תמיכה במספר הקצאה (חשבוניות ישראל) מעל התקרה הקבועה בחוק — דורש חיבור API לרשות המסים. מה סף הסכומים של חשבוניות בעסק?
3א. **מה חסר בשירותים הקיימים חוץ מהמחיר?** לתעד כאבים ספציפיים מ-Xterm/Morning/Ypay (UX? דוחות? אוטומציה?) — כדי שלא נשחזר אותם.
4. **תשלומים:** רק תיעוד תקבולים, או גם סליקה בפועל (אשראי / העברה / ביט)?
5. **רב-מטבעי:** שקל בלבד או גם מט"ח (חשבונית ללקוח בחו"ל)?
6. **Stack:** ברירת המחדל של הבית (TypeScript + Next.js + Postgres/Supabase) או משהו אחר?

## דרישות ליבה (טיוטה ראשונית)

- הפקת חשבונית מס / קבלה / חשבונית מס-קבלה / חשבונית עסקה / חשבונית זיכוי.
- מספור רציף לכל סוג מסמך; מסמך שהופק אינו נמחק ואינו נערך — תיקון בזיכוי בלבד.
- חישוב מע"מ אוטומטי לפי שיעור בתוקף בתאריך המסמך.
- ניהול לקוחות: פרטים, ח.פ/ע.מ, יתרות פתוחות.
- PDF חתום-מראה + שליחה במייל.
- ייצוא נתונים לרו"ח.
- Audit log על כל פעולה (עקבי עם עקרונות SUPER-MESHINE).
